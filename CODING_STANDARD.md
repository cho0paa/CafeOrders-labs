# Стандарт кодування проєкту CafeOrders

## 1. Загальні положення

1.1. Стандарт діє для всього коду рішення `CafeOrders` (варіант № 12: замовлення та меню кав’ярні):
бібліотеки `CafeOrders.Core` і консольного застосунку `CafeOrders.App`.

1.2. Мова коду, імен і повідомлень комітів: ідентифікатори — англійською, коментарі,
XML-документація й повідомлення комітів — українською.

1.3. Зміна не приймається, якщо `dotnet build` дає хоча б одне попередження або
`dotnet format --verify-no-changes` завершується з кодом, відмінним від 0.

## 2. Іменування

2.1. Імена беруться зі словника предметної області: замовлення — `Order`, рядок замовлення —
`OrderLine`, позиція меню — `MenuItem`, гість — `Guest`. Синоніми (`Client`, `Dish`, `Bill`) для
тих самих понять заборонені.

| Сутність | Конвенція | Приклад | Антиприклад |
| :--- | :--- | :--- | :--- |
| Клас, запис | PascalCase, іменник | `OrderLine` | `orderline` |
| Інтерфейс | I + PascalCase | `IOrderRepository` | `Repository` |
| Метод | PascalCase, дієслово | `CalculateTotal` | `calc` |
| Властивість | PascalCase, іменник | `UnitPrice` | `GetUnitPrice` |
| Булева властивість | префікс Is / Has / Can | `IsRegular` | `Regular` |
| Приватне поле | _ + camelCase | `_lines` | `m_Lines` |
| Локальна змінна, параметр | camelCase | `totalAmount` | `ta` |
| Константа | PascalCase | `MaxLineCount` | `MAX_LINES` |
| Перелічення | PascalCase, однина | `OrderStatus` | `OrderStatuses` |

2.2. Скорочення заборонені, крім загальновживаних `Id` та `Sku`; однолітерне ім’я дозволене
лише лічильнику циклу `for`.

2.3. Транслітерація (`zakaz`, `kolvo`) та числові суфікси (`sum1`, `Total2`) заборонені.

## 3. Форматування

3.1. Відступ — 4 пробіли; табуляція заборонена.

3.2. Довжина рядка — не більше ніж 100 символів.

3.3. Фігурні дужки — стиль Allman (відкривна дужка на новому рядку); дужки обов’язкові навіть
для однієї інструкції в тілі `if`, `else`, `for`, `foreach`, `while`.

3.4. Між членами класу — рівно один порожній рядок; два порожні рядки поспіль заборонені.

3.5. Директиви `using` — на початку файлу, поза простором імен; системні перші; невживані
видаляються.

3.6. Простір імен — файлового рівня (`namespace CafeOrders.Core.Domain;`).

3.7. Один файл — один тип; ім’я файлу дорівнює імені типу.

3.8. Кінці рядків — LF, кодування — UTF-8, у кінці файлу — один порожній рядок.

## 4. Коментарі та документація

4.1. Коментар пояснює «чому», а не «що». Коментар, який переказує код, видаляється.

4.2. Закоментований код у репозиторій не потрапляє: історію зберігає Git.

4.3. Кожен публічний тип бібліотеки `CafeOrders.Core` має XML-коментар `<summary>`
(для всіх публічних членів — з лабораторної роботи № 4).

```csharp
// погано: коментар переказує код
// додаємо рядок до списку
_lines.Add(line);

// добре: коментар пояснює причину рішення
// ціну фіксуємо в рядку: меню може подорожчати, а чек гостя змінитися не повинен
UnitPrice = menuItem.Price;
```

## 5. Структура проєкту

5.1. `CafeOrders.Core` — уся логіка предметної області; у ній заборонені звертання до `Console`
та файлової системи.

5.2. `CafeOrders.App` — введення й виведення; посилається на `CafeOrders.Core`. Зворотне
посилання заборонене.

5.3. Сутності предметної області лежать у теці `Domain` і просторі імен `CafeOrders.Core.Domain`.

5.4. Грошові величини мають тип `decimal`, дата й час — `DateTimeOffset` або `DateOnly`.

## 6. Правила комітів

6.1. Повідомлення — за Conventional Commits: `тип: суть` у наказовому способі, перший рядок —
до 72 символів. Типи: `feat`, `fix`, `docs`, `chore`, `style`, `refactor`, `test`.

6.2. Один коміт — одна завершена зміна; після коміту проєкт збирається без попереджень.

6.3. Теки `bin`, `obj` і файли `*.user` не комітяться (перевіряє `.gitignore`).
